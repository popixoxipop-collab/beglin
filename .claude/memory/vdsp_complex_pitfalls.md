## vDSP 복소 커널 함정 (2026-07-03/04 M1 Max 실측, 상세: /Volumes/D50/vdsp)

**패리티 (PyTorch↔vDSP):**
- P1: `torch.fft.irfft`는 DC/Nyquist 허수부 무시 → C에서 재구성 직전 `imag[0]=imag[N/2]=0` 필수
- P2: `fft_zrip` packed 포맷(DC/Nyquist packing+2×스케일)은 패리티의 적 → 먼저 `fft_zip`+Hermitian 미러로 검증 (달성: 1.49e-8)
- P3: vDSP FFT inverse는 N배 → 1/N 곱하기
- P4: PyTorch GELU 기본은 erf형 → C에서 `erff` 사용 (tanh 근사는 ~1e-3 오차)

**커널 선택:**
- P5: `zconv`는 미최적화 — 실수 conv보다 25× 느림 → 복소 conv는 무조건 FFT-conv
- P6: `ctoz/ztoc` = memcpy 2배 → 저장부터 split-planar (DSPSplitComplex 레이아웃)
- P7: 원소별 복소 연산(zvmul 등)은 clang -O2 자동 벡터화와 동급 — vDSP 승리는 초월함수 대체/패스 융합뿐 (zvphas 2.16×, zcoher 2.19×)
- P8: `zmmul`은 지연 중립(0.96×) — ComplexLinear는 압축 레버(파라미터 −50%)지 속도 아님

**복소 NN 학습:**
- P9: `z.abs()` gradient는 0 근처 NaN → safe-abs `sqrt(re²+im²+1e-6)`
- P10: 무작위 복소 필터 init은 시드 1/3이 dead plateau(+60%) 포획 → identity 근처 init(w≈1+0i)+residual skip

**양자화 (RTN × 복소, 2026-07-04):**
- P11: group-64 RTN에서 in_f가 64 안 나눠지는 작은 레이어는 group 강제 축소 → q-오차 지배 (geo_w0 g=6 → q4 6.48e-4, 복소 필터의 ~3300배). 방어: 64배수 zero-pad/fp16. "group=64=무손실"은 거짓(레이어 민감도 별개)
- P12: 복소 필터는 q4 강건(dense의 1/3000, Cartesian≈Polar) — **무조건**(선형 spectral-multiply 한정). sparse band-mask 90%에서도 q4 degradation 0.00%. 이유: RTN Cartesian 오차는 Re/Im 절대-bounded+선형 propagate(phase 폭증은 상대-오차 착시), phase오차 큰 작은빈=에너지 최소빈. 레버4(복소압축)×q4=5.95× 곱 성립.
- **P11 q8 확장 — group 페널티는 비트폭에 둔감(2026-07-16 재실행, `results/RESULTS_RTN_QUANT.md` q8 열)**: `quant/rtn_complex_experiment.py` 재실행, 2026-07-04 전 수치 4자리까지 동일 재현(결정론적 RTN). **원래 q4뿐이던 per-tensor 표에 q8을 채우자 q4 순위가 q8에서 보존되지 않음이 드러남** — q4: geo_w0 > inp_w > geo_w1 > out_w / q8: geo_w0 > geo_w1 > out_w > **inp_w(2위→4위)**. 4→8bit nominal 기대는 16×인데 실측이 두 무리로 갈림: **강제축소 group(geo_w0 g=6, geo_w1 g=32)+out_w는 9.4~10.9×(nominal 미달, 비트 줘도 안 사라짐) vs inp_w는 149.7×(nominal ~9배 초과)**. → `inp_w`의 q4 오차는 group이 아니라 **비트 해상도 한계**였고, geo_w0/geo_w1은 **group 구조 탓**. P11의 "group 강제축소=회피가능한 명백한 페널티"가 비트폭 무관 구조 문제임이 확정되고, q8에선 상위 2개를 강제축소 텐서가 독식해 신호가 더 선명. **단 이건 parity 레벨 진술 — R5대로 정확도와 분리**: 같은 ckpt에서 q8 full +1.42% / q4 full +1.35% 둘 다 게이트 PASS(`RESULTS_QUANT_ACCURACY.md` ①)라 **"q8 배포에 zero-pad 필요"로 읽으면 안 됨**(표는 방어 예산의 *우선순위*지 필요성 근거가 아님).
- **★위 항목의 자체 오류 정정(2026-07-16)**: 2026-07-08 세션 요약과 그 리포트(https://claude.ai/code/artifact/a30ad0a1-41de-4387-bdb5-3b90dc200435)는 "8bit에서도 **동일 순위**로 재현"이라 주장했으나 **실측하니 거짓**(inp_w 2→4위). 당시 검증된 건 "geo_w0 최악 / vis 무손실" 두 점뿐인데 순위 전체로 일반화했고, 거기서 "int8 배포에도 zero-pad 필요"라는 R5 위반 결론(parity≠정확도)까지 파생시킴. 2026-07-16에 그 요약을 근거로 메모리에 그대로 옮겨적었다가 repo 문서를 읽고서야 발각 — **CLAUDE.md §12 "이전 세션 요약의 완료/확인됨 주장은 가설로 취급" 사례가 vdsp에서도 재현된 것**. 교훈: 재실행 로그의 *일부* 수치 일치를 전체 일치로 확대하지 말 것. 또한 P12의 phase 반증 정량근거(magnitude 0.128~0.701/near-zero 0.0%/corr 0.098~0.166/decile 평탄/init bias 원인)는 2026-07-08의 "새 발견"이 아니라 **이미 2026-07-04에 `RESULTS_RTN_QUANT.md`에 전부 기록돼 있던 것** — 메모리만 보고 "새 발견"이라 판단하기 전 repo 문서부터 확인할 것.

SGD 20-step 학습 궤적을 PyTorch torch.optim.SGD와 step-by-step 대조 — 전 스텝 오차 <3e-7(train_vdsp.c). **핵심 유도 결과**: irfft의 backward = rfft(grad_output)를 genuine bin(DC/Nyquist 제외)만 2/n, DC·Nyquist는 1/n로 스케일; rfft의 backward = grad_output의 genuine bin만 절반으로 스케일한 뒤 irfft 적용 후 n배. vDSP/Accelerate 자체엔 자동미분이 없지만, **forward pass 재현에 그치지 않고 backward+optimizer까지 전부 vDSP 연산으로 리팩터링 가능함을 실증**(단, 미분 유도는 사람이 직접 해야 함 — 자동미분 엔진이 생기는 게 아니라 그 결과를 수동으로 재현하는 것). parity/{vdsp_nn_ops_backward.h,.c, gradcheck_main.c, train_vdsp.c, gen_grad_reference.py, gen_train_reference.py}.

- **로컬 학습 가능 파라미터 크기 실측(2026-07-08)**: vDSP-only 학습(위 항목)의 스텝 시간을 SpectralTrunk 폭 W=64~16,777,216(파라미터 20,720~2,365,599,152=23.7억)까지 실측 확장. **벽 없음, 전 구간 작동**: <1000만 파라미터는 10ms/step 이내(반응성 있는 실험 가능), 1000만~23.7억은 10ms~2.7초/step(학습 자체는 되지만 인터랙티브하진 않음). 23.7억 파라미터에서 ~20GB 메모리, 2693ms/step. **23.7억에서 의도적으로 중단**(기술적 한계 아님) — 측정 당시 실제 Nemotron-8B LoRA 학습(`mlx_lm.lora`, ~5.6GB RSS)이 이 머신에서 동시 실행 중이었고, 다음 단계(2^25, ~44억)는 ~40GB 필요해 그 job과 메모리 경합 위험이 커서 공유자원 안전 기준으로 멈춤(vm_stat/ps로 Nemotron job 건강 상태 실시간 확인하며 진행, 실제로 전혀 영향 없었음 확인). **이 M1 Max 로컬 기준: 적어도 23.7억 파라미터까지 vDSP 학습이 작동함을 실측 확인**(더 큰 스케일은 다른 무거운 job 없을 때 재측정 필요, 미측정을 추측으로 채우지 않음). 현재 배포 모델(W=256, ~48K)은 이 여유의 극히 일부만 사용 중. parity/bench_train_scaling.c, results/RESULTS_TRAINING_SCALING.md.
- **2^25(~44억) 실측 시도 + 진짜 버그 발견(2026-07-08)**: 메모리 압력이 실제로 green(64GB 중 32GB 사용)임을 사용자가 스크린샷으로 확인해줘서 재시도. **1차: 즉시 SIGSEGV**(malloc 실패가 아니라 `w_dim*FUSED_DIM*sizeof(float)`류 계산이 `size_t` 승격 전에 32bit `int`로 먼저 곱해져서 W=33,554,432에서 `w_dim*64=2,147,483,648`=INT32_MAX+1로 **실제 오버플로우** 발생). `size_t` 캐스팅+`xmalloc`(NULL 체크) 수정 후 **2차 시도는 32.8GB까지 정상 성장**(수정이 진짜 원인이었음 확인)했으나 이후 로그·크래시리포트 없이 프로세스 소멸(OS 메모리압박 종료로 추정, log show로 확정은 못함). **Nemotron job은 두 시도 모두 전혀 영향 없음**(2초 간격 폴링+RSS 39GB/job사망 시 자동 kill-switch로 안전 확보). 결론(임시): 23.7억(2^24)은 확정 작동, 44억(2^25, ~40GB)은 이 시점 동시 실행 중이던 Nemotron job과의 메모리 경합 속에서 미완주로 추정 — 경계는 이 인접한 두 2의 거듭제곱 사이.
- **정정: Nemotron 경합이 원인이 아니었음, 실제로는 2번째 버그(2026-07-08)**: Nemotron job 종료 후 메모리 완전히 비어있는 상태(~51GB 가용)에서 2^25 재시도 → **또 SIGSEGV**(경합 가설 반증). vDSP FFT 자체를 격리 테스트(`test_vdsp_fft_size_limit.c`, log2n=25)했더니 문제없이 작동 → vDSP 라이브러리 한계 가설도 반증. 실제 원인: `sgd_update()` 호출부(`sgd_update(inp_w, grad_inp_w, w_dim*FUSED_DIM, ...)`)가 malloc 수정 때 놓친 **동일 클래스의 int32 오버플로우**를 그대로 갖고 있었음(길이 인자가 여전히 `int`, 호출부에서 `size_t` 캐스팅 없이 곱셈). `sgd_update` 시그니처를 `size_t n`으로 바꾸고 호출부 캐스팅 → **재시도 성공: W=2^25 → 47억 3118만 파라미터, 9065.9ms/step, ~40GB**. **교훈: 크래시가 "라이브러리/하드웨어 한계처럼 보여도" 먼저 주변 코드의 오버플로우부터 의심할 것** — 이전의 "공유자원 경합으로 안전하게 중단" 서사는 틀렸고 그냥 버그였다. results/RESULTS_TRAINING_SCALING.md 정정 반영.

- **이식성 실증: FFTW로 동일 backward 재구현+검증(2026-07-08)**: "수학은 이식 가능, 코드는 라이브러리별 재검증 필요"라는 주장을 실제로 검증. FFTW3 설치(brew) → r2c/c2r 컨벤션 실측(`test_fftw_convention.c`: unnormalized forward, unnormalized inverse, **vDSP와 달리 DC/Nyquist packing 없이 N/2+1개 명시적 bin** — PyTorch/NumPy와 동일 레이아웃) → 이 컨벤션 기준으로 backward 처음부터 재유도 → **유도 결과가 vDSP용과 수학적으로 완전히 동일**(irfft backward=rfft(grad) genuine×2/n+DC/Nyquist×1/n, rfft backward=n×irfft(genuine bin 절반)). FFTW+순수 C 루프(BLAS 전혀 없음, Apple 코드 0줄)로 완전히 독립적인 2번째 구현(`fftw_nn_ops.*, gradcheck_fftw.c`) 작성 → 동일 PyTorch grad_reference.bin 대조 → **전부 PASS, vDSP판과 동일한 1e-9~1e-10 정밀도**. 결론: vDSP의 packed 포맷 트릭은 순수 저장형식 디테일이고(vdsp_rfft/irfft 래퍼 뒤에 숨겨짐), 일단 "unnormalized-forward+N/2+1-bin+수동 1/n-inverse" 계약만 지키는 백엔드라면 backward 수식은 라이브러리 무관 — vdsp_nn_ops.h 추상화 경계가 옳았음을 검증. **이식 안 되는 건 실제 vDSP/Accelerate 코드 자체**(Windows/Linux엔 FFTW/MKL/OpenBLAS로 같은 방식의 스왑 필요, 여기선 gradient-check 스케일까지만 검증, 속도 비교/전체 학습루프 궤적 재검증은 안 함). results/RESULTS_PORTABILITY_FFTW.md.

**판별 기준:** 위상이 결과에 살아남고 + 초월함수/다중 패스를 제거하는 연산만 복소화. dot/matmul은 실수(ANE/BLAS) 유지.
**핵심 수치:** FFT-domain 레이어 crossover 없음(폭 256부터 3×, 상주 시 48~3260×), 도메인 크로싱이 상주층의 27배 비용.
