# Beglin Hierarchical Tupper Grid-of-Micro-Experts — offline experiment (2026-10-13)

## Experimental status

**OFFLINE SYNTHETIC: PASS for exact assembly, reproducible factorization contrast.**
**REAL PRETRAINED MODEL: NOT RUN / UNVERIFIED.** XOX `Tailnet Commander` returned 404/429 and `Remote Desktop Commander` reported its monthly usage limit. No live inference endpoint, weights, deployment, or `main` branch was modified.

The aim is to test *micro-expert assemblies inside ordinary MoE experts*, rather than treating every binary pixel in a fixed 106×17 Tupper image as an independent trainable matrix.

## Architecture

For a macro-expert `e` with `intermediate=1408`, `hidden=2048`, let channel width `c` divide 1408. Its SwiGLU FFN is an exact assembly:

`FFN_e(h) = Σ_{g=0}^{1408/c-1} D[e,g] ( SiLU(G[e,g] h) ⊙ (U[e,g] h) )`

In exact mode **all channels execute**. Joint permutation of corresponding `G/U` rows and `D` columns preserves the function. In a proposed future sparse mode, a second-stage micro-router selects a subset and may introduce error; it requires separate model-quality evidence and probably retraining.

| Channel width c | Micro channels per macro expert | Micro channels across 64 macro experts | Selected top-6 macros, all micro channels |
|---:|---:|---:|---:|
| 16 | 88 | 5,632 | 528 |
| 32 | 44 | 2,816 | 264 |
| 64 | 22 | 1,408 | 132 |
| 128 | 11 | 704 | 66 |

Nested example: 22 **parent assemblies** of 64 neurons, each with 4 children ×16 neurons; 64 macro experts at the top layer. Generalized Tupper `N = intermediate / c, M = num_experts` is the binary micro-router activity mask. `k=N·Σ_{e,g} A[g,e] 2^(N·e+g)` decodes exactly, but **does not compress weights**. Coefficients and weights are a separate representation; do not materialize gigantic decimal `k` in the hot path.

## Methods and source identity

- Dimensions: **64 macro experts × 1,408 intermediate × 2,048 hidden × 3 matrices**, all evaluated in 11 tiles of 128 intermediate rows, total **553,648,128 synthetic scalar weights** per experiment. No 64-dimensional toy hidden size.
- Same full synthetic expert pool for c ∈ {16,32,64,128} within each condition; source seed `20261013`, latent lane `16`, rank `2`; train experts 16, holdout experts 48, individual expert coefficients estimated from 20% of coordinates, scores on distinct 80%.
- *Structured positive*: each 16-neuron lane generated from an anchor plus its own 2 shared basis patterns and expert-specific coefficients plus Gaussian noise. This deliberately favors width 16; it is a **fixture, not a discovery**.
- *Independent negative*: each scalar independently Gaussian, same dimensions and storage budgets.
- FP16 roundtrip shared dictionary and expert coefficient values. The residual and pure Q4 use group-64 symmetric rounding **numerical proxies**; Beglin's real qNg64 error-feedback bit-plane packing and CPU/GPU kernels were not exercised.
- Synthetic simulation implementation SHA256 (`hierarchical_moe_probe_v1_synthetic.py`): `17105a3c9794d743307ab02b60b6d2b5a0ef56a3c80f77c02b395bc20ab1a7ff`. Two JSONs record same implementation digest. The updated `hierarchical_moe_probe.py` additionally supports a **read-only real Safetensors mode**, independently unit-tested on fake fixtures, but not executed on pretrained weights.
- Per-experiment runtime: positive 115.924 s; negative 114.872 s on this container. Peak RSS roughly 1.4 GB per process. No GPU inference timing.

## Channel sparsity (quality FAIL)

Top-six macro experts; width 16 has 88 micro channels each, total 528 active in exact mode. Remove 50% of child channels based on a *calibration input's actual output magnitude*, then evaluate a different input: the resulting relative expert-output L2 error was **0.701**. An oracle that already computed the *test input's actual* full channel outputs (not deployable as a speedup) produced **0.392**. At 25% retained, static error was 0.826. The static strategy is not a successful learned second-stage router. Any claim of lowered runtime FLOPs would require fused sparse execution benchmarks; current calculations only estimate selected FFN work.

## What is known vs unknown

**Established:** arbitrary `N×M` Tupper masks round-trip, exact FFN micro-assembly with full native tensor shapes, all four width variants compared fairly on the same synthetic weights, independent negative control correctly fails, and a read-only Safetensors loader can reconstruct BF16/F16/F32 unfused Expert tensors into `[G,U,D.T]` tiles.

**Not established:** common-law structure of a pretrained LLM, channel-16 optimality on actual DeepSeek-V2-Lite, any valid compressed representation at the real qNg64 bitstream level, workload logits/perplexity/token agreement, routing stability, CPU/GPU throughput, lossless weight reconstruction after hybrid quantization, optimized hierarchical routing, or real model production readiness.

## Reproduction

```bash
python -m pip install numpy scipy
OPENBLAS_NUM_THREADS=2 python hierarchical_moe_probe_v1_synthetic.py --mode structured --output fullshape_structured.json
OPENBLAS_NUM_THREADS=2 python hierarchical_moe_probe_v1_synthetic.py --mode independent --output fullshape_independent.json
OPENBLAS_NUM_THREADS=1 python -m unittest discover -v
```

For a REAL local unfused HF DeepSeek-V2-Lite checkpoint, after a verified full checkpoint-identity receipt, run an **isolated scratch** probe with `hierarchical_moe_probe.py`:

```bash
OPENBLAS_NUM_THREADS=2 python hierarchical_moe_probe.py \
  --checkpoint-index /secure/path/model.safetensors.index.json \
  --layer 1 --experts 8 --train-experts 4 --top-k 3 \
  --hidden 2048 --intermediate 1408 \
  --groups 16 32 64 128 --output /scratch/beglin_real_moe_l1_8e.json
```

The code reads weight shards via bounded tile-shaped mmap (not production service) and refuses unexpected shape/type/keys. It currently *does not align neurons across macro experts*; such an alignment may be necessary to discover a real common basis and cannot be inferred from a failed unaligned result. Full 64-expert probing should follow only after real 8-expert I/O validation. `index_sha256` and file timestamps in its output are **not full checkpoint identity**.
