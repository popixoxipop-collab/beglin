## 핵심 판정

**196개 투영 텐서에 대해 BF16 활성값 기반 품질 대리 지표와 실제 Apple CPU 커널·Q/K/V·gate/up 병렬 비용을 결합하는 MILP 정밀도 할당기가 작동한다. 28계층 실제 BEGLIN 전체 모델에서 정책 실행과 실제 pthread 병렬 forward도 구현·검증됐다. 하지만 선택 정책은 전체 4비트 대비 품질·속도·메모리에서 모두 열세였으며, 전체 모델 병렬 실행에도 안정적인 속도 이득이 없다.**

따라서 연구 프로토타입 **구현 PASS**, 새 할당 품질 우월성 **미입증/개발 평가 열세**, 비동기 속도 승격 **REJECT**. 자동 정책 승격·운영 배포는 허용되지 않는다.

## 1. 실제 수행한 작업

1. **원본 BF16 활성값 수집 — Alienware CUDA.** 공식 pinned `Qwen/Qwen2.5-1.5B-Instruct` 리비전 `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`을 수정하지 않고, 28계층 × 7종 투영 모듈 **196개**의 입력 채널 제곱 평균을 forward prehook으로 수집했다. 공개 보정 문장 12개, 총 **461토큰 위치**. 통계 원본은 Alienware 사용자 홈 비공개 디렉터리 `0600`. CUDA 수집 성공. 196개 텐서의 원본 BEGLIN Q4G64 및 qNg64 n8 양자화와 활성값 기반 **국소 출력 복원 오차 감소** 계산은 CPU 3작업자 병렬 실행으로 완료됐다. 전체 출력 인과 민감도·Hessian 또는 NLL을 직접 측정했다는 주장은 금지.

2. **진짜 Apple CPU 병렬 투영 단계 측정.** Q/K/V의 8가지 비트 조합과 gate/up의 4가지 조합을 실제 BEGLIN 네이티브 커널로 측정했다. `serial_q4_6t`, `parallel_q4_1t`, `parallel_q4_6t` 비교; 각 동시 Q4 연산에 **독립 q4pool**을 사용한다. 작은 단계별 연산에서 QKV는 1.13~1.55배, gate/up은 1.06~1.90배의 최선 병렬 이득을 관찰했다. **이는 전체 LLM 지연 개선이 아니다.**

3. **196개 텐서/28계층 MILP 비트·커널 할당.** 계층당 7개 역할의 4·8비트 조합 **128개**, 총 3,584개의 이진 선택지에서 단계별 하나를 고르는 SciPy HiGHS 정수 최적화를 수행했다. 실제 압축 바이트, 원본 BEGLIN 순차 커널 비용과 QKV·gate/up 실측 동시 실행 단계 비용을 제약으로 넣었다. 8비트 승격 정확히 28개, 4비트 168개, 투영 메모리 ≤830,570,496바이트, 순차 예측 ≤100ms, 가상 병렬 DAG 예측 ≤90ms. 소스만 사용한 MILP 결과는 `status=0`, `mip_gap=0`으로 고정됐다. 원본 소스 12문장에만 의존하며 평가 문장/정답은 사용하지 않았다.

4. **실제 28계층 전체 모델 시험.** Apple EOE 네이티브 BEGLIN C 격리 바이너리에 위의 마스크를 적용했다. 공개 **평가 문장 8개/예측 토큰 131개**가 모든 조건에서 동일하다는 SHA 잠금 영수증을 확인했다. 실험 모델은 Qwen BF16 원본에서 가중치를 추출하되, FP32 기준은 BF16을 FP32로 확장한 연산이지 실제 BF16 런타임이 아님.

5. **실제 전체 모델 pthread Q/K/V·FFN 병렬 실행 검증.** 소스 고정 정밀도 마스크 `9324c5ec891d638f2713d3bbd4187399e1aae8a9a74df129dfabc4e8ea870212`로 native serial/async 각각 실행했다. QKV/gate-up pthread 완료 후 의존 단계에 합류했고, 최종 로짓은 **바이트 일치**, PPL도 완전 일치했다. 다만 속도 이득이 없었다.

**결론:** 이 개발 평가에서 전체 Q4G64는 새 Qv2보다 **PPL·지연·RSS·투영 가중치 바이트 네 기준 모두 우위**다. Qv2를 품질이나 전반적 효율의 개선으로 표기하면 안 된다. 기존 무작위 혼합은 Qv2보다 PPL이 낮으나 더 느리고 메모리를 많이 사용하므로, 모든 지표에서 전체 Q4만 선택해야 한다는 뜻은 아니다.

병렬 실행의 CPU 스레드 경쟁·스케줄링·join 비용은 독립 투영 연산에서 얻은 이득을 상쇄했다. 표본 수가 적으므로 작은 차이의 통계적 결론까지 주장하지 않는다. 병렬 승격 최소 5% 이득이라는 추가 보수적 기준은 **사후 공학적 안전 게이트**이지 사전 등록된 통계적 판정 기준이 아니다. 따라서 기본 native async 실행은 `OFF`.

## 5. 다음 연구의 올바른 우선순위

1. **현재 Qv2 자동 승격은 계속 OFF.** 메모리·속도를 우선하면 전체 Q4가 개발 기준에서 더 적합하다. NLL 우선이면 실험용 seed73 혼합이 좋았으나 속도/메모리 비용 증가와 작은 개발 표본을 반드시 명시.
2. **활성값 2차 모멘트만으로 품질을 예측할 수 없다는 부정적 결과를 보존**하고, 이후에는 허용된 독립 데이터에서 목적함수 품질 민감도 추정 자체를 개선해야 한다. 다른 모델·다른 장르·다른 길이에서 검증하기 전 가설 채택 금지.
3. **비동기 full-model 최적화는 병렬 이득 확인을 조건으로** 실행. 소규모 stage 병렬의 이점만으로 GPU/CPU serving latency 절감을 주장하지 않는다. 실제 multi-request, 적은 수의 독립 Q4 threadpool, worker affinity, M>1 prefill 및 measured p95로 검증한 이후만 승격 검토.
4. 모든 실험은 격리 연구 브랜치·비공개 수집물에 유지. `main`, 원본 HF 모델, Tailnet Commander immutable 운영 릴리스는 건드리지 않는다.

**공학적 결과는 확보했지만, 현재 가중치·활성값 품질 대리 점수 기반 Qv2 비트 선택과 전체 pthread 병렬화는 자동 기본값으로 사용할 근거가 없다.**
