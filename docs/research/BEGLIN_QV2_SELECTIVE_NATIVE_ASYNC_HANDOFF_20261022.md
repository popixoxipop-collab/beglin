# BEGLIN Qv2 — 활성값 기반 국소 양자화와 조건부 비동기 병렬 실행 핸드오프

## 1. 최종 판정

**비트폭 × 실제 실행 커널 × 실행 그래프(Q/K/V 및 Gate/Up의 동시 처리)를 함께 고려하는 연구용 할당·실행 구조는 구현되었다.**

그러나 현재 공개 합성 개발평가 결과에서는 **(1) 새로운 활성값 기반 28/196 텐서 할당 정책의 품질 우위가 없고**, **(2) 실제 전체 모델의 무조건 비동기 또는 선택적 병렬 실행도 확실한 속도 향상을 증명하지 못했다.**

따라서 **비동기 기본값 OFF**, **원본/새 정책 자동 승격 금지**, **Q 연구 가설 NO_VERDICT** 유지한다.

## 2. 실제 수행 범위와 확인된 증거

### 활성값 기반 정밀도 선택

- Alienware RTX 5070 Ti에서 공식 SHA 고정 `Qwen/Qwen2.5-1.5B-Instruct` 원본 **BF16** 체크포인트를 로드했다.
- 사전 동결 공개 보정 문장 **12개, 461개 토큰 위치**에서 **28계층 × 7종 투영 = 196개** 원본 입력 채널의 제곱 평균을 forward hook으로 수집했다.
- 사전 보정 모멘트로 각 텐서의 **활성값 가중 국소 출력오차 근삿값**을 계산했다. 동일 스토리지·원본 압축 기준의 네이티브 4비트(Q4G64) 대 8비트(qNg64) 코드 오차를 3개 CPU 작업자로 계산했다.
- 이는 입력 채널 상관관계를 생략한 **diagonal second-moment** 대리지표일 뿐, 최종 로짓·NLL에 대한 인과 민감도나 Hessian이 아니다. 이전에 차단됐던 원본 전체 모델 텐서별 출력 교란 실험을 재시도하지 않았다.
- Q/K/V 및 FFN Gate/Up 단계를 독립적으로 모델링한 병렬 실행 그래프에 네이티브 Apple CPU 역할별 커널 비용을 반영했다. 추가 모델 검증에서는 별도 448변수 MILP/7역할 정수 선택 등이 사전 동결된 경로를 사용했다.

### 해당 정책의 전체 네이티브 모델 품질

모든 후보는 동일한 **공개 합성 개발용 문장 8개·131개 예측 토큰**에 대해 평가됐다.

| 기준/할당 | PPL (낮을수록 좋음) |
|---|---:|
| 원본 BF16 소스에서 FP32로 확장한 기준 | **348.3639** |
| 기존 Seed73 무작위 혼합(28×8bit / 168×4bit) | **552.7020** |
| 전체 Q4G64 | **727.9173** |
| 활성값+비동기 비용 고려 MILP 혼합 | **827.4999** |

이는 사전 동결된 개발 입력에 대한 실제 BEGLIN 전체 Qwen 결과다. **새 활성값 가중 대리지표는 이 데이터에서 기존 무작위 혼합이나 전체 4비트보다 품질이 낮았다.** 일반화 성능·실제 작업 AUROC·V6 24개 사용 기록과의 겹침은 검증되지 않았다.

## 3. 진짜 pthread 병렬 실행에서 발견한 문제

기존 전체 비동기 시도는 실제로 Q/K/V 투영을 두 worker + 호출자, Gate/Up을 별도 worker + 호출자로 실행했고, 동기화는 모든 후속 소비자 전에 수행했다. 각 역할은 독립적인 Q4 1/6 스레드풀을 사용했다. 하지만 기존 전체 ON/OFF 측정은 평균 직렬 **93.62ms**, 비동기 **93.6567ms**였다. 같은 전체 로짓과 131개 위치 PPL을 보존했지만 속도 이득이 없었다.

추가로 소스 SHA가 고정된 네이티브 Qwen C 실험 사본을 생성해 **QKV만, Gate/Up만, 둘 다, 모든 직렬 × Q4 1/6 스레드**를 같은 28개 8비트 선택 텐서와 같은 원본 모델로 비교했다. 원본 Qwen 엔진이나 운영 코드는 건드리지 않았다. 각 모드는 워밍업 후 단일 토큰 네이티브 benchmark(best-of-three)를 **정방향 및 역방향 총 2회** 실행했다.

| 실행 모드 | 2회 평균, ms/토큰 | 직렬 대비 |
|---|---:|---|
| 직렬(원본 native OFF) | **91.735** | 1.000배 |
| Q/K/V만 6스레드 병렬 | 100.405 | 0.914배 |
| Gate/Up만 6스레드 병렬 | **91.515** | **1.0024배** |
| Q/K/V + Gate/Up 모두 6스레드 | 97.555 | 0.940배 |
| Q/K/V만 1스레드 병렬 | 97.875 | 0.937배 |
| Gate/Up만 1스레드 병렬 | 125.905 | 0.729배 |
| Q/K/V + Gate/Up 모두 1스레드 | 131.745 | 0.696배 |
| 원래 동결된 레이어별 병렬 설정 | 92.085 | 0.996배 |

- **가장 빠른 Gate/Up만 6스레드**조차 평균 속도 차이가 약 **0.24%**이므로, 보수적 **두 번의 실행 모두 5% 이상 개선** 기준에 크게 못 미쳤다.
- 동일한 실험 바이너리에서 직렬과 선택된 후보의 **151,936개 원시 로짓 파일 SHA가 동일**했다. 동일한 공개 합성 131 위치의 PPL도 **827.4999 / 827.4999**로 일치했다.
- 실제 native pthread join counters로 각 모드가 의도한 QKV/GU 단계만 병렬화함을 확인했다. 따라서 단순히 `async=1` 로그만 보고 병렬화라고 주장한 것이 아니다.
- PPL 프로세스 RSS (직렬/선택된 후보): 약 **4.869GB / 4.870GB**. 실제 최종 코드/모델은 격리 scratch에만 저장됐다.
- 이 시험은 **best-of-three 단일 토큰 지연 2회**로서, 연속 TPS, 사용자 요청 동시성, 발열, 메모리 스트레스나 에너지 절감은 증명하지 않는다.

## 4. 비동기 그래프 비용의 설명력

실제 Apple CPU 단일 투영 단계의 이전 소스 전용 측정값을, 동결된 28개 계층 비트 패턴에 대입했다. QKV 단계가 낙관적으로 절약하는 시간은 약 **2.155ms/토큰**, Gate/Up 단계는 약 **2.435ms/토큰**, 합계 약 **4.590ms/토큰**이다.

기존 전체 모델 평균 직렬 **93.62ms**를 5% 개선하려면 **4.458ms** 이상의 절감이 필요해, 추가적인 pthread join/락·캐시·코어 경합에 허용되는 예산이 **약 0.131ms**뿐이다. 이는 단일 계층 비용을 합한 *낙관적 정량 추정*으로 **엄밀한 하드웨어 상한은 아니지만**, 전체 모델 비동기가 독립 단계 개선분을 대부분 잃는 사실과 부합한다.

그래프를 고려한 할당에서는 반드시 **비트별 커널 비용뿐 아니라 실제 stage/barrier 경합 비용**을 학습해야 하며, 더 많은 worker를 단순히 추가해서 해결할 수 있다고 가정하면 안 된다.

## 5. 새 fail-closed 조건부 스케줄러

새 연구 바이너리는 `BEGLIN_QV2_NATIVE_ASYNC=1`에서만 `BEGLIN_QV2_NATIVE_STAGE_POLICY`를 읽는다. 허용 모드: `frozen/qkv6/gu6/both6/qkv1/gu1/both1`. 기존 `BEGLIN_QV2_NATIVE_ASYNC=0`은 완전한 원본 직렬 경로다.

스케줄러와 검증 스크립트는 **전체 로짓·PPL 일치, SHA 고정, 반대 순서 2회 benchmark, 반복된 5% 개선 조건**을 검사한다. 입력·근거 누락/다른 체크포인트/잘못된 실행 모드일 때는 실패로 막는다.

검사 결과:

- **실험 통과:** 네이티브 단계 분기·진짜 병렬 pthread·출력/품질 일치.
- **속도 승격 실패:** 1.0024배(0.24%)는 1.05배 속도 조건 미충족.
- **기본값:** `BEGLIN_QV2_NATIVE_ASYNC=0`·단계 `serial`. **자동 활성화는 수행하지 않는다.**
- **검증:** 선택적 분기 회귀 **8/8 PASS**, fail-closed admission **5/5 PASS**, 기존 Q kernel-aware 회귀 **8/8 PASS** → **21/21 PASS**.

## 6. 후속 진척 조건

1. **정밀도 품질:** 현재 diagonal activation local score는 공변량·후속 레이어 전파를 무시해 전역 PPL과 불일치한다. 허용된 독립 보정 자료에서 채널 간 공분산 또는 국소 출력 오차의 더 나은 대리지표를 측정하되, 기존 차단된 per-tensor 전체 로짓 교란 실험을 우회하지 않는다.
2. **비동기 이득:** Stage-only 이득의 거의 전부가 barrier 비용에 상쇄됐다. 스레드 수·worker 풀 예산·실제 코어 경합·지속 처리량·여러 동시 요청을 실측한 새로운 독립 데이터에서 **>5% 반복적 이득**을 증명해야 default ON을 재검토한다. Apple Metal overlap은 검증되지 않았다.
3. **안전:** native 기존 산출물은 공개 합성 개발 샘플만 사용했다. V6 과거 24개 사용 문항/배포 QA, 실제 작업 AUROC, 복수 모델·Mac CPU/Metal/Alienware GPU, 장시간 발열·동시성 스트레스는 여전히 미완료다.
4. **릴리스:** 운영 `main`과 immutable G6 operator 릴리스 승격 금지. 이번 작업은 GitHub 연구 브랜치의 별도 코드·영수증만 저장한 상태.

**정리:** 커널 인식 비트 할당과 native 비동기 실행/조건부 admission은 **공학적으로 구현 완료**. 다만 **속도 우월성·품질 우월성은 둘 다 미입증**이므로 운영 기본값은 직렬을 유지한다.
