## 5. 비동기/병렬의 실제 결론과 다음 안전한 작업

**병렬화 기능은 실제로 존재한다.** Q/K/V 및 gate/up은 수학적 의존성에 맞춰 독립 계산 후 join할 수 있도록 네이티브 CPU 연구 엔진에 연결됐고, 로짓·PPL은 기존 순차 실행과 동일했다. **성능은 자동 활성화 기준을 통과하지 못했다.** 따라서 v3에도 디코더 전체 pthread 병렬을 강제 활성화하지 않고 안전한 순차 기본 경로를 썼다.

현 단계의 가장 큰 병목은 정밀도별 최적 커널의 부재보다는 **질 좋은 텐서별 승격 대상을 선택하는 대리 품질 지표**다. 단순 Frobenius → 대각 활성값 → 비대각 공분산까지 고도화했지만 세 방법 모두 공개 개발 평가에서 기준을 뛰어넘는 일반화된 정책을 만들지 못했다. 후속 논문 가설이나 실제 운영에 대한 주장은 다음 단계를 충족하기 전까지 금지한다.

- **소스/평가 분리 유지:** 다른 장르·길이·모델과 신규 독립 공개 자료에서 순서·중복·원래 사용했던 V6 24개 출처의 오염을 감사한다.
- **품질 목적 재설계:** 다운스트림 NLL 연관성을 학습·검증할 수 있는 별도 허용된 보정 관측치가 확보되면 품질 대리 지표를 갱신하되, **이전에 차단된 개별 텐서 전체 모델 출력 개입 실험을 다른 경로로 우회하지 않는다**.
- **성능 재현:** EOE 시스템 부하가 낮고 다른 워커와 CPU 리소스가 격리된 환경에서 sustained TPS/p50·p95, 동일 바이너리 ABBA, 네이티브 pthread ON/OFF, 복수 요청·에너지·Metal 지원을 평가한다. 현재 CPU overload 시점의 수치로 자동승격 금지.
- **운영 안전:** `main`, Qwen 원본, immutable `operator.900387`, live Metal GPU·자동 정밀도 정책을 변경하거나 승격하지 않는다. 원본 v6 `VERIFIED_NO_HIERARCHICAL_GAIN` 판단은 그대로 유지.

**현재 판정:** CPU 커널·압축/bit 선택·실제 동시 실행의 엔지니어링 실증은 충분히 진행됐다. Qv3 공분산 정책도 개발 평가에서 성능 우위를 입증하지 못했고, 품질 기반 할당 및 비동기 기본값 자동승격은 **계속 차단**한다.
