# BEGLIN Q — qNg64 8비트 Apple NEON SIMD 엔진 핸드오프 (2026-10-22)

**브랜치:** `popixoxipop-collab/beglin` → `research/oml-acs-prereg-20261021`  
**종합 판정:** 실제 Apple Silicon에서 **qNg64 n=8 비트플레인 압축 형식은 유지**하고 기존 스칼라 matvec를 실험용 NEON 16-code 디코더로 교체했다. 단일 텐서·4종 실제 Qwen 텐서 형태·전체 Qwen2.5-1.5B 28계층에서 수치 정합성을 통과했다. **단일 텐서 약 9.64배, 전체 8비트 디코드 약 9.11배, 혼합 28×8비트+168×4비트 약 5.6배** 빨라졌다. 본 변경은 격리 실험 바이너리에만 적용했으며 **운영 승격·최종 Q 수용은 하지 않았다.**

## 1. 왜 수행했나

앞선 Q 실험에서는 BEGLIN이 Qwen2.5-1.5B 196개 투영 텐서에 실제 packed Q4G64 / qNg64(n8)를 적용하는 기능을 실증했지만, 스칼라 qNg64 디코더가 극심한 병목이었다.

- 전체 qNg64 8비트: 약 **0.19 tok/s**.
- 8비트 28개, 4비트 168개: 약 **1.23 tok/s**.
- 전체 Q4G64: 약 **13.29 tok/s** (기존 6개 Q4 작업 스레드).
- 가중치 오차로 택한 28개 승격 정책은 동일 비용의 고정 무작위 정책보다 PPL이 나빴다. 이를 결과에 맞춰 재선정하지 않았다.

이 단계는 **실행 커널 병목 개선**이지, 과거에 실행이 차단된 텐서별 **실제 출력 민감도 선택 실험**을 다른 수단으로 재시도한 것이 아니다. 전자는 실행했지만 후자는 여전히 미완료다.

## 3. 수치 정확도와 속도: 실제 텐서

처음에는 실제 L0 `q_proj` (1536×1536), qNg64 압축 데이터와 정규화된 실제 토큰 임베딩 **96개**를 사용했다.

| 지표 | 결과 |
|---|---:|
| 기존 qNg64(n8) scalar GEMV 중앙값 | 9.343ms/벡터 |
| NEON SIMD 중앙값 | **0.969ms/벡터** |
| 속도 개선 | **9.64×** |
| 새 NEON−기존 scalar 최대 절댓값 차이 | **7.63×10⁻⁶** |
| 상대 L2 | **3.74×10⁻⁸** |

이어 Qwen BF16 원본 캐시의 **서로 다른 4종 실제 텐서 모양**을 검증했다.

| 텐서 | 모양 (out×in) | scalar→NEON 속도 개선 | 최대 출력 오차 |
|---|---|---:|---:|
| L0 k_proj | 256×1536 | 9.69× | 2.38×10⁻⁷ |
| L14 o_proj | 1536×1536 | 9.56× | 2.38×10⁻⁷ |
| L0 gate_proj | 8960×1536 | 9.73× | 2.38×10⁻⁷ |
| L0 down_proj | 1536×8960 | 9.74× | 5.96×10⁻⁸ |

다른 입력 모양 8960은 난수 시드 고정 합성 활성값으로 검증했으므로, **실제 문맥 FFN 활성값**이라는 주장은 하지 않는다. 연구용 수치 허용범위 `max_abs<0.0005, rel_L2<1e-5`를 모두 통과.

## 4. 전체 BEGLIN Qwen2.5-1.5B native 모델 실측

아래 속도는 **워밍업 8토큰 후 native BEGLIN 벤치마크 내부의 단일 토큰 3회 중 최단 시간**이다. 토큰 처리 분포나 지속 처리량과 혼동하지 않는다.

| 정책 | 이전 scalar 8비트 | NEON 8비트 | 속도 향상 |
|---|---:|---:|---:|
| 전체 qNg64 n8 / 196개 | 0.190 tok/s | **1.732 tok/s** | **9.11×** |
| 기존 가중치 오차 기반 혼합 / n8 28개 | 1.234 tok/s | **6.924 tok/s** | **5.61×** |
| 기존 시드73 무작위 혼합 / n8 28개 | 1.233 tok/s | **6.952 tok/s** | **5.64×** |

전체 모델 검증:
- 원본 scalar n8 대비 새로운 8비트 전체 로짓 151,936개, **최대 차이 2.38×10⁻⁵**, 상대 L2 `8.97×10⁻⁷`; 상위 10토큰 10/10 일치.
- 두 혼합 정책의 scalar 대비 로짓 상대 L2는 각각 `8.26×10⁻⁷`, `1.73×10⁻⁶`. Top-10 10/10 일치.
- 새 커널 실제 호출 건수: 전체 8비트 dump **1,960**, benchmark **11,172**, PPL **4,508**. 두 혼합 모델은 dump 각 **280**, benchmark 각 **1,596**, PPL 각 **644**. 이 실험들의 n8 scalar fallback **0**.

### PPL·최대 RSS 확인

동일한 **공개 합성 채팅 두 개 / 정답 토큰 21개**의 teacher-forced PPL이다.

| 정책 | 이전 PPL | NEON PPL | NEON PPL 작업의 최대 RSS |
|---|---:|---:|---:|
| 전체 n8 | 2148.1101 | **2148.1231** | 별도 실측 없음 |
| 오차 기반 혼합 | 4747.6975 | **4747.6983** | 약 4.92 GB |
| 무작위 혼합 | 3411.2256 | **3411.2283** | 약 4.92 GB |

PPL 상대 변화는 세 정책 모두 **0.001% 미만**. 기존 오차 기반 정책이 무작위 정책보다 **품질이 나쁜 실패 결과**는 그대로다. 커널을 빠르게 고친 것만으로 최적 비트할당 문제가 해결된 것이 아니다. 기존 전체 4비트의 약 **13.29 tok/s**에는 아직 못 미친다.
